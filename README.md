# Visit China AI V6.6 · 可信RAG、对话服务与反馈迭代

**个人项目 · 产品与运营设计 · AI辅助实现。** 面向北京、上海、广州、深圳、香港的入境服务原型；城市覆盖深度不同，上海工具最完整。模型、知识、页面行动和运营候选分层处理，不将平台链接当真实订单。

## 本轮增量

- **情境服务卡**：酒店、铁路、机票、自驾、司机接送、一日团和餐饮；查看、备选、暂不需要，与本轮回答和明确偏好关联。
- **模拟产品接口**：`POST /api/products`准备白名单查询条件，返回公开提供商入口；明确无价格、库存、订单、自动预填或服务商请求。
- **出发时段**：历史高铁表保留日期标记；时段快选和精确上下界共用交集，重绘保留席别与时间，条件冲突需修正。
- **一次解决反馈**：不重复询问CSAT；保留可选脱敏上下文，未解决或低电量/弱网时不推延伸服务。
- **运营目标预设**：减少漏召回、减少弱相关、先结论后行动；手动、反馈及Loop候选使用共同验证器，展示同批比较，支持重验收、人工发布和回滚。
- **保留原能力**：23项提示词和调用契约核对；不删除原指令，不降低模型预算，不训练权重，不改变原有语音和五账号行为审核边界。

## 技术与规模的准确口径

- 5,000个官方URL索引不等于5,000篇现行正文均已核验。标准KB为来源指纹绑定的有限登记问法，其余问题仍走模型与检索。
- RAG为BM25 + 稀疏TF-IDF + RRF + 规则重排，辅以有界多查询、来源/城市/时效检查；不是学习型Embedding或神经重排，没有Milvus。
- 上下文、明确选择、事实资料和程序策略逻辑分开，不是Redis五层记忆平台。本地SQLite，云端状态沿用私有Blob条件写。
- 历史20,000条合成回归、5,000条增量检索和12,000条Loop用途不同；既有同批Loop新增175条目标召回不等于线上准确率或收入。
- 服务接口是mock adapter；“收藏”与“打开Trip.com/美团”等不创建订单，不计GMV。
