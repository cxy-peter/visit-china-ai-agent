# V6.5｜知识闭环增量发布

基线：V6.4 main `23872e914aa4c54df09762ead2ce29ec81078c83`。本轮是应用改造，没有模型权重训练。

## 已接入代码的变化

- 共享五城别名与范围：北京、上海、广州、深圳、香港；香港不继承未明确适用的内地资料。上海路线仍有独立覆盖边界。
- 5个双语标准KB条目，精确匹配10个已登记问题变体。只有来源有效、未变更且指纹匹配才能直出；无Key也可用只读公开KB接口。不是任意问句均可免模型。
- 沿用已有模型生成的retrieval_query，保留原问、检查约束，在同一快照上有限融合，不增加改写模型调用。
- 候选先检查来源／城市／明确渠道，再做展示评分；不直接拼接未经冲突核验的多份回答。
- 运营展示KB、查询计划与候选门禁；KB不进入检索非空率分母。更新Loop执行指纹，历史候选不能直接覆盖新逻辑。

完整说明见 [技术实现与运营闭环](V6_5_TECHNICAL_GUIDE.md) 和 [原提示词保留与本地接续](V6_5_PRESERVATION_AND_HANDOFF.md)。

## 已取得的验收及恢复记录

中断前的应用提交`db0386340c36a72ff6f2f86f8fb1d6da8571b027`已通过[CI 36164850146](https://github.com/cxy-peter/visit-china-ai-agent/actions/runs/36164850146)：424项程序／接口检查，29项五城KB／运营浏览器检查，19项V6.4兼容浏览器检查，以及原有20,000条合成回归。恢复工作先下载并核对了该次真实工件，没有重新编造计数。

恢复阶段另加`tools/verify-v65-preservation.cjs`，逐字核对原意图和生成提示词，检查关键模块、Flash／Pro预算与超时。当前提交的结果应以最新CI为准，不把基线通过自动视为新检查通过。报告在GitHub Actions的`v65-validation-evidence`工件下，包括`acceptance.json`及`prompt-preservation.json`。

所有上述程序、语料和浏览器检查均为开发／合成／受控验收，不是线上用户量、模型正确率、真实麦克风或新付费模型调用。48项浏览器检查使用实际浏览器和本地HTTP，模型部分为测试fixture。结果由实际命令生成，旧版本数字不直接改名成本轮结果。

工作容器不能进行浏览器localhost验收，使用GitHub Actions上的独立运行。代码合并、Vercel部署和生产端真实模型验收是三个不同状态；不把Git提交等同于线上实测。
