# V6.5｜知识闭环增量发布

基线：V6.4 main `23872e914aa4c54df09762ead2ce29ec81078c83`。本轮是应用改造，没有模型权重训练。

## 已接入代码的变化

- 共享五城别名与范围：北京、上海、广州、深圳、香港；香港不继承未明确适用的内地资料。上海路线仍有独立覆盖边界。
- 5个双语标准KB条目，精确匹配10个已登记问题变体。只有来源有效、未变更且指纹匹配才能直出；无Key也可用只读公开KB接口。不是任意问句均可免模型。
- 沿用已有模型生成的retrieval_query，保留原问、检查约束，在同一快照上有限融合，不增加改写模型调用。
- 候选先检查来源／城市／明确渠道，再做展示评分；不直接拼接未经冲突核验的多份回答。
- 运营展示KB、查询计划与候选门禁；KB不进入检索非空率分母。更新Loop执行指纹，历史候选不能直接覆盖新逻辑。

完整说明见 [技术实现与运营闭环](V6_5_TECHNICAL_GUIDE.md)。

## 验收

程序与接口、两组浏览器和历史2万条离线回归分别记录在 `evidence/v6.5/` 及该提交CI。全部为开发／合成／受控检查，不是线上用户量、模型正确率或新付费模型调用。结果文件由实际命令生成，不把旧版本测试数直接改名成本轮结果。

工作容器未能进行浏览器localhost访问；采用GitHub Actions上的独立浏览器运行。CI未完成前不视为发布成功。Vercel是否完成生产更新应另看部署状态，不把Git提交等同于线上实测。

## 保留边界

本轮不增加通用KB后台编审器、不接真人Zendesk、不做自动全双工、不接订单库存、不承诺五城同等服务。新批准别名仍由源码受控修改和测试发布。公开文档不含公司截图、内部OKR、真实凭据或私人简历联系方式。
