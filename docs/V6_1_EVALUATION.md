# V6.1：20,000 条评测、轮换话术与可追溯验收

## 交付边界

这是一套 **20,000 条去重的组合合成回归用例**，不是 20,000 条真实用户日志，也没有执行 20,000 次 DeepSeek API 请求。它检查实际本地路由、站点图、数值工具、多轮纠正、自动 RAG 召回、证据准入和反馈建议分类。模型意图质量、回答忠实性、真实用户解决率仍需单独的真实模型／人工标注评测。

保存全部历史 1,221 条用例的 ID、输入、预期和历史上下文；原始 `data/evaluation/v5.9-cases.json` 未被覆盖。额外 10 条历史基础场景继续由原有 `scenario-eval.js` 执行，所以 Operations 的完整检查包含 **20,000 + 10** 条。

不是通过随机编号、标点或无意义后缀扩充。路线问题改变真实站点组合，纠正案例改变上一轮端点和当前修改，车费改变实际数值边界；服务查询结合位置和任务。**同一模板家族仍存在相关性，20,000 条不能当作 20,000 个独立随机样本计算置信区间。**

`v6.1-manifest.json` 保存完整家族分布、去重率、来源分布和语料 SHA-256。构建程序对 Unicode、空格和句末标点归一化去重，保留数值小数点，避免把 3.75 公里误合并为 375 公里。

## 固定留出集和每轮新话术

固定划分通过语义组 SHA-256 的模5结果产生；同一路线、同一来源等已归并组不跨 development / holdout。普通轮换只使用 development，按家族分层轮转，种子负责可复现排序。

状态文件保存语料版本、已使用 ID、轮次和种子。改变种子不会清空“已使用”集合；同一状态中跨轮不会重新抽到旧问题。耗尽时明确报告剩余数量，**不会悄悄循环旧问题**。失败问题同样记为已使用，仍可按 ID 或完整回归单独重放。

这里的固定 holdout 用作稳定回归集合。本轮完整验收已查看它的失败并修复通用实现，因此**不能再声称它是从未查看的盲测集**。下一轮需要衡量泛化能力时，应新增未参与修复的人工标注真实问法，另设封存集。

```powershell
# 可复现构建；不覆盖历史 v5.9 数据
node tools/build-scenario-corpus.cjs

# 完整运行全部 20,000 条，默认不调用付费模型
node tools/run-corpus-evaluation.cjs

# 每轮不同话术；保持同一个 state 路径实现跨轮去重
node tools/run-corpus-evaluation.cjs --sample 120 --seed week-1 --round round-1 --state runtime/evaluation-sampling.json --output evidence/v6.1/round-1.json
node tools/run-corpus-evaluation.cjs --sample 120 --seed week-2 --round round-2 --state runtime/evaluation-sampling.json --output evidence/v6.1/round-2.json

# 只有显式指定才采样固定留出集
node tools/run-corpus-evaluation.cjs --sample 120 --split holdout --seed release --round release-holdout --state runtime/evaluation-sampling.json --output evidence/v6.1/release-holdout.json
```

## 验收结果与真实修复

最终全量结果：**20,000 / 20,000 通过**，本机一次运行约 **10.6 秒**。两轮各120条均通过，240个问题 ID 无重复，均未使用 holdout；全部为离线检查，付费模型调用数为0。

首轮保存了 **416 条真实失败**，包括当时尚未合并的48条 TenPayGo 资料。没有把错误意图或错误数值改成“预期通过”。主要修复：

- 英文 `rail tickets ... not the metro` 不再误入地铁。
- “目的地换成X，继续从刚才那站……”不再被后面的“从”改成起点。
- 周浦东→周浦等长短站名重叠能找到第二个实际出现位置。
- 有明确地铁历史的英文改起点，不再被同名景点推荐抢占。
- 3.75、38.5 等里程上的一分钱浮点舍入误差得到纠正，保留等候费、附加费和北京燃油项。
- “外滩”“Xintiandi”等明确命名实体不再被两词匹配门槛排除。
- 扩充真实服务资料后暴露5条地铁 QR / Alipay 问题被机场、车站词淹没：降低地点前缀词的权重、保留具体服务请求权重；没有按问题 ID 或指定来源硬塞结果。

## 相同检索实现下的性能与准入

`rag.compile(records, config)` 只为显式固定快照预分块、统计词频和文档向量，`retrievePrepared` 对每个不同问题执行相同 BM25、稀疏 TF-IDF、RRF 与父文档去重。评测没有跳过问题，也没有以预期答案替代实际检索。

生产 `retrieve()` 每次从当前资料重新构建，没有隐式全局缓存，因此停用、过期、发布版本变化即时影响准入。快照不能改城市／分块参数继续复用；测试检查预编译与普通调用结果完全相同。

证据评分 **大于60** 才进入自动生成的 RAG 片段；60及以下进入待核验范围。这个门槛不能绕过停用、过期、城市和纯索引过滤。评分是证据检查分，不是事实正确概率。新闻不覆盖正式政策；TenPayGo 的名称和能力依据官方资料，不能据此肯定上海地铁刷闸机支持或全部服务已上线。

## Operations 使用方式

“问题排查”展示用户主动分享的最多8轮脱敏上下文、原始问题、当时答案、引用、执行 ID、问题说明、建议分类与处理记录。管理员可手动分类、补资料、授权 DeepSeek 总结／回放，或者从问题生成技能候选。候选仍需核对验收后发布，工单关闭不会改写用户勾叉评价。

“指标大表”将解决率、反馈覆盖、CSAT、人工意图标注、检索有结果率、建议点击、平台外跳、完整回答P95、留存执行失败、工单回放和关闭放在同一张表，显示分子分母、时间窗口、所需事件和解读限制。未接入的真实订单、GMV/ROI、转人工、退出和情绪准确率明确标“未接入”；没有数据不显示0%。

### 运营页直接轮换

“Loop 与评测”保留完整20,010条验收按钮，同时增加 **“下一轮120条新问法（免费）”**。这个按钮实际运行被抽到的120条，不是只展示一个抽样列表。轮次、种子、各类型通过数、失败样例和剩余未使用问题会保存在结果中。

`sample-eval.evaluate(store, {seed?, count?})` 在持久存储 CAS 事务里先预留问题 ID，再调用同一 `corpus-eval` 实现。默认120、上限300；服务器只接受 development，拒绝客户端指定 holdout 或付费调用。运行中断的预留题仍视为已使用，避免重试后偷偷重复。保存最近200轮元数据，但已使用 ID 集合不会因轮次裁剪而清空。

后台只返回压缩后的结果（所有总数、分组统计，最多80条失败和20条通过样例），以免把2万行全部塞进运营页面和云函数响应。完整离线报告仍在证据目录。`v5/sample-eval.test.js` 验证两个持久存储实例并发抽样不重叠、holdout和额度模式不可注入、300条上限、耗尽不循环，以及中断后不重用。
