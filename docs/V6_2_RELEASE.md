# Visit China AI V6.2 验收与使用说明

2026-09-25 · 个人项目，AI辅助实现。访问地址：https://visit-china-ai-agent.vercel.app/?v=6.2

## 本轮交付

- **语音耐心与插话**：完整句等待约2.6秒；“然后、还有、因为”等未完句约4.2秒。浏览器自动重启识别时保留已完成片段。播报与模型处理期间保持识别；不同于当前播报的有效输入可自动暂停播报。静音、挂断、授权错误仍停止采集；只有单字或无效片段不触发回答。
- **补充当前问题**：生成期间输入或开始有效说话，会暂停旧请求，保留此前问题；补充发送后按更新后的上下文重新生成，迟到的旧结果不能覆盖新轮。没有修改或展示模型内部思维链。
- **JCB证据纠正**：新增上海市口岸服务办公室及JCB官方资料，先回答符合条件的卡支持直接拍卡过闸，再说明芯片、免密及余额要求。不要求用户披露额度，不把未披露信息推导为不支持。直接拍卡、购票、绑定支付应用分别解释。
- **路线卡与导出**：长宁区慢游；上海抗战纪念地按市中心、宝山、金山分区规划。卡片包含顺序、计划时刻、公开地址、地图、来源、已覆盖片区的吃住与酒店总机；支持Markdown、CSV、JSON导出及修改出发时间。纪念地参观顺序不是军事进攻顺序；计划时间不是实时交通/开放承诺。没有核对的周边餐饮住宿明确留空。
- **Flash / Pro**：对话设置选择自动、Flash或Pro。自动采用可解释的复杂度规则，主题路线、适用条件和纠正倾向Pro；普通查询倾向Flash。模型请求独立，访客之间不会相互改变模式。
- **正文自动入库**：证据不足时，从已有官方索引择一抓取实际正文，让DeepSeek自评并逐字校验摘录；分数≥60可入库，<60进入复核材料。抓取失败、冲突、明确失效、运营暂停等硬限制仍保留。Source library也提供管理员手动获取正文入口。分数不是校准后的正确概率，5,000条索引并不等于5,000份已获取正文。

这些话术是已有人工定义场景及来源问题的表达变式，标签不变，有来源与生成方式标记；不是12,000个独立人工标注意图。本轮不调用付费模型、不改权重。Operations → 技能与自动验收展示结果；每次新实验预留不同话术区间，达到至少10,000条才接受完整实验。

**线上发布边界**：线上的支付宝来源已因正文变化暂停引用，资料指纹与离线基线不同。因此本轮候选未自动发布到线上；保留候选、参数、证据和重新跑线上全样本的入口。只有对应当前资料/技能版本的候选通过检查后，才由管理员发布，支持回滚。

## 资料与架构

- JCB与路线官方依据：[证据清单](V6_2_JCB_AND_THEME_ROUTES.md)。
- 共享检索继续使用BM25、稀疏TF-IDF、RRF及文档去重；增加模型检索词的第二轮检索和证据对齐生成。正文没有通过边界检查时不进入事实回答。
- 本轮没有引入Milvus或Neo4j。JCB问题首先是证据解释和输出校验，换向量数据库不能直接修好。后续若长文本近义查询持续漏召回，再引入向量检索并和当前基线比较。Milvus官方入门：https://milvus.io/docs/milvus_lite.md 。
- 现在是结构化工具与有来源的RAG；两类完整路线有受约束的规划工具。其他区域/主题可走一般资料问答，尚不保证都能生成相同丰富度的可导出路线卡。
- 部分浏览器/扬声器组合仍可能发生回声或识别延迟。当前自动插话用AEC与播报文字过滤，不是声纹识别；保留手动打断和文字输入。

## 体验入口

刷新V6.2页面，在右上角DeepSeek连接/输入框设置中选择模式。使用VC-开头的体验码，或先登录Operations再用管理员连接；sk-开头的DeepSeek API Key仍只放服务端。已有私人体验码不因发布而改变。

可以依次试：
1. 我想用JCB银行卡直接拍卡坐上海地铁，没有告诉你额度会影响判断吗？
2. 我想逛长宁区，十点出发，把附近吃饭和住宿按顺序排进去。
3. 改成十一点半开始，酒店先不要了。
4. 上海有哪些抗战纪念地？分三天安排，想看看附近能吃什么住哪里。
5. 模型正在回答时，直接补充一句需求；播报时也可直接插话。
