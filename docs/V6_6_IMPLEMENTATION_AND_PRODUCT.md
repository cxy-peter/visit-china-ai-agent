# Visit China AI V6.6｜实现、迭代与运营交接

2026-09-25。个人产品项目，主导需求与运营设计，AI辅助工程实现。基于V6.5增量修改，不移植示例项目的学校背景、组件或指标。五城为北京、上海、广州、深圳、香港，覆盖深度不同；上海仍有较完整的历史路线工具。

## 1. 背景与迭代逻辑

项目从自己的入境旅行原型迭代而来，并非接手学院系统。游客需要知道下一步做什么，运营需要知道为什么没有解决、应该改哪层。早期问题包括车站名被误当购票意图、中文城市名导致已召回资料被过滤、回答之后缺少可保留的行动选择，以及反馈未形成可验收的配置改动。

V6.4逐步解决分项需求、自动RAG、来源与反馈关联；V6.5增加版本绑定的标准KB、有限多查询及城市/候选适用性检查。V6.6补上情境服务卡、模拟适配接口、铁路时段和运营目标预设。迭代路径是“问题—定位—最小改动—回放—确认发布”，不把版本数量当多年生产经验。

## 2. Harness与可信RAG

实际阶段为：输入/会话版本 → 权限与预算 → 标准KB判断 → 初次检索 → 结构化意图 → 按任务补充检索或工具/生成 → 引用/数字/范围检查 → 回答与行动 → 反馈。不是强行套用Intent先行的五步DAG；标准KB可直接退出，事实工具和复杂生成也有不同分支。

模型负责语义理解和表达，应用负责工具允许范围、资料生命周期、预算、有限修正和版本核对。多需求某项失败不吞掉其他结果。Trace是执行阶段及检查结果，不是模型隐藏推理。

资料为5,000个去重官方URL索引，其中原1,114条有正文采集元数据，其余链接不自动等于已读正文。默认520字符切片、60重叠、top-k=8、覆盖阈值0.06；BM25与稀疏TF-IDF经RRF及规则重排，保留父资料/片段版本。没有Milvus、神经Embedding或Cross-Encoder。

有限多查询保留原问题，复用已有检索短语，检查地点、数字、渠道与否定条件，没有新加三次改写调用。5个双语标准KB条目、10个登记问法仅在精确匹配、来源有效且指纹一致时直出；复杂请求仍走原模型链路。香港不自动继承内地适用资料。

文件：`v5/assistant.js`、`model-intent.js`、`rag.js`、`retrieval-plan.js`、`kb-direct.js`、`answer-guard.js`、`city-scope.js`。

## 3. 上下文与策略分离

旅程状态保存已确认需求和语言；回答记录带答案ID和来源；`choice-memory.js`只保存当前标签页的备选、收起状态及铁路筛选。事实资料和程序性配置分开，不让用户偏好、会话推断或提示词变成官方依据。

新选择记忆使用sessionStorage，最多100条，加载时清理超过4小时的旧条目；新聊天清空。它不是Redis，不是严格实时TTL服务，也没有五个独立Memory数据库。保存备选不创建订单，不自动成为所有后续模型请求的语义记忆。

## 4. 回答下的延伸服务

七类入口：铁路、机票、酒店、自驾租车、带司机接送、一日团/体验、餐饮。按本轮任务最多显示三张；用户拒绝、已订对应产品、未解决、低电量、弱网或付款资格咨询时，抑制不相关推荐。正文和事实判断不因此替换成推销模板。

卡片支持查看选项、留作备选、暂不需要和恢复。点击不打断语音，不改变预订状态，重绘保留选择。自驾与司机接送分开；自驾资格、年龄、押金由实际服务商另行核验。所有平台入口为公开查询链接，不是佣金合作或实时库存声明。

## 5. 模拟产品接口与铁路时间

`POST /api/products` 同时接入本机Node和`api/products.js`。仅接收白名单JSON，限制12KB、同源、合法地点/日期/席别/时段，不接收任意URL。字段：product、city、origin、destination、language、date、after、before、seat。

返回 `mode:mock-adapter`、查询条件、缺失字段与公开提供商入口；明确 `price:null`、`inventory:null`、`bookable:false`、`prefilled:false`、`bookingCreated:false`、`providerRequestSent:false`。提供商没有收到这些条件；用户到外部平台需重新确认。接口超时保留本地选择，不编造报价或替代订单。

铁路表保留2024-06-15历史记录标记，新增上午/下午/晚上快选和精确最早/最晚时间。筛选与接口共用时段交集，矛盾条件提示修正，日期未给不补今天，上海站和虹桥不互换。历史票价不能称为当前售价。

文件：`product-suggestions.js`、`product-api.js`、`related-services-ui.js`、`choice-memory.js`、`transport-ui.js`。

## 6. 一次反馈与指标口径

保留一次“有帮助·已解决 / 还没解决”，未解决可分类并自愿附脱敏上下文。改选更新同一个回答，不生成两个分母。运营关闭工单不能改掉原用户反馈。

交互合并不表示CSAT与解决率统计等价。新主指标是用户确认解决率，配合反馈覆盖率；旧CSAT独立保留。无反馈为未知，检索非空不等于正确，卡片曝光/平台外跳不等于订单。收藏、模态窗口打开及完整订单漏斗未全部单独埋点，不虚构GMV或转化提升。

## 7. 低门槛运营与共同自动验收

新增三个目标：减少漏召回（top-k加2，上限12）、减少弱相关片段（最低覆盖加0.02，上限0.4）、先结论再行动（有界表达要求）。它们只是候选，不保证收益。

手动参数、目标预设、反馈规则、大样本Loop与既有授权模型建议最终使用共同候选契约。快速验收通常21项：16条上海检索问题加资料与边界检查；不是五城完整语义测评，更不能证明表达更好。界面展示同批基线/候选、改善/退化及配置、资料、评测器指纹。

一键重验收保留最近五次旧记录；最新待审候选默认展开。发布前重跑并核对基线及哈希，来源URL、类型、范围、正文、复核条件或代码变化都会要求重新检查。自动通过不自动发布，管理员仍需看实际问答并确认；原五账号行为策略审核不变，也不是所有知识编辑都要五票。

受控测试验证：top-k=8 → 目标候选 → 自动验收 → 显式发布 → 下一次检索读取top-k=10与新版本 → 回滚至8。只证明参数实际生效，不声称必然返回十条资料或准确率上升。

文件：`harness.js`、`skill-presets.js`、`ops-api.js`、`ops-harness-ui.js`、`loop-evolution.js`。没有任意代码生成发布、完整在线灰度分桶或自动收益回滚；语义改变仍需人工或明确授权的模型回放。

## 8. 历史结果与本轮验收分开

V6.4保存的同批12,000条Loop：目标召回11,482→11,657，改善175、退化0，仍有343未命中，约增1.46个百分点。它不是本轮重新训练或线上解决率。新增5,000条89.7%是另一集合，不与前者直接作版本提升；原20,000条是合成/资料改写回归。

本轮首轮452项程序通过，浏览器因候选折叠导致“重验收”不可见而失败；修复UI自动展开并强化可见性断言，没有强制点击。又发现仅选上午时表格和请求条件不一致，改为共同交集。旧兼容检查使用“一日团”标签，保留该用户术语而非删测试。

最终数量、提交与失败记录见`V6_6_RELEASE.md`和CI工件。所有新测试使用受控模型/本地HTTP，未重新做付费DeepSeek、真人语音或生产订单验证。

## 9. 原Prompt与能力保留

`tools/verify-v65-preservation.cjs`保留23项核对：原提示词文本、模型适配、Auto/Flash/Pro预算、超时、语音与行为治理。V6.5的五城补充保留，V6.6不删原指令，不下调Pro预算，不训练权重。

这些检查证明源代码和调用契约保留，不证明任何真实问题绝无退化。V6.6改变的检索/候选/界面仍需新样本检验。免费路径也不冒充通用模型输出，模拟适配器不冒充真实商户接口。

## 10. 本地更新与后续

先停止旧服务并保存未提交修改、.env和运行数据，再执行：

```bash
git status
git pull --ff-only origin main
npm ci
npm test
npm run voice:check
npm run build
npm start
```

发生分叉不强行覆盖。本地进程内存Key重启需重新配置。GitHub合并不等于Vercel已部署或模型已授权。下一步先做新标注问法、真实语义与手机语音验收，再接供应商库存/订单，不为模仿范文增加MongoDB、Redis、Milvus或K8s。

产品设计调研见[来源与采用决策](V6_6_DESIGN_RESEARCH.md)；公开简历表述见[V6.6项目描述](V6_6_RESUME_PUBLIC.md)。公司OCR、OKR、私人联系方式与密钥不在公开仓库。
