# Visit China AI V4：从需求确认到有依据的抵达计划

日期：2026-09-24。个人产品验证，不是携程、机场、政府或实习公司的正式项目。

## 1. 这次完成了什么

V4 使用普通 UTF-8 源码，位于 `v4/`，不依赖旧版失败的压缩分包。默认可运行；启用真实外部能力需要启动 Node 服务，并在本机 Operations 配置自己的 DeepSeek Key。这里的“已接入”指代码调用正式接口，不代表本次已经使用真实 Key 完成付费模型联调。

主链路：

用户分次输入 → 编号的需求草稿 → 用户勾选并确认 → 检索官方来源 → 受控访问原文 → 按节点生成行动 → 出示依据和检查记录 → 用户确认完成／仍然卡住。

不是先输出长篇攻略，再让用户把信息抄回表单。需求未确认不能调用计划接口；新输入会撤销旧确认。城市不明确时，不套用上海的机场位置。极低电量时优先保留一张求助卡，不继续加载照片、语音和交易推荐。

## 2. 对话与生成

默认模式：确定性规则整理需求、提供已经人工阅读核对的短摘要。它不能理解所有自然说法，界面明确标记默认模式。

模型模式：服务端 POST `https://api.deepseek.com/chat/completions`。本次核对的官方模型名为 `deepseek-flash` 和 `deepseek-v4-pro`；使用 JSON Output 和关闭 thinking 的请求参数。第一类调用整理用户需求；第二类调用根据已经取得的官方正文生成某个行动节点。模型不是只做意图分类。

每张节点给出：要完成什么、具体动作、简短的安排理由、仍待确认的条件、引用来源、检查时间、来源抓取状态、正文哈希和运行检查记录。安排理由是面向旅客的决策解释，不展示模型私有推理链。

请求处理中仍可输入补充。旧请求取消，旧版本结果不得覆盖新需求。前端收到实际 NDJSON 进度与节点后更新界面，不用固定计时器伪造生成过程。这是节点级流式传送；模型响应本身仍是一次完整 JSON，不是逐 Token 语音通话。

## 3. 1,114条官方记录，准确意味着什么

第一轮真实网络采集：2026-09-24 17:17:59–17:38:00 UTC。

- 上海政府英文网：600个去重页面。
- 北京政府英文网：514个去重页面。
- 合计：1,114个成功获取且 URL、正文归一化哈希均去重的文章页面。
- 原始目标1,200未完全达到；最低1,000条达成；没有达到5,000条。

官方记录不是1,114条“现行规则已人工审核”的保证。来源包括公共服务、抵达交通、支付通信、目的地介绍及历史活动信息。主题标签可重叠：公共服务537、目的地373、活动参考259、抵达交通106、支付通信56。正文日期范围为2020-05-12至2026-09-24；部分网页更新日期不等于事件仍有效。

库中保留：原始URL、标题、发布站点、城市、主题、网页日期、抓取时间、HTTP状态、正文哈希、最多20词原文片段和外链图片信息。没有将切片计成新记录，也没有公开镜像整篇第三方文章。内容的开放访问不意味着图片或正文可任意再授权。

`data/official/collection-report.json` 是数量口径；`records.jsonl` 可用于后续索引；`audit/` 包含访问、跳过、失败和去重日志。图像链接未全部独立核验，不作为“可用图片数量”。

另有7张逐条阅读过的来源卡，涵盖微信收费、浦东服务、上海地铁、铁路护照购票、北京机场、北京支付入口、支付宝开发者介绍。7张来源卡并不保证包含7项完整现行政策，也不与1,114机械相加。支付宝收费仍有明确缺口。

生产建议：先从高频任务所需的少量关键页面建立可运营的审核队列，再扩大覆盖。资料量、当前有效性、用户问题覆盖率和答案正确率必须分别测量。

## 4. 手续费：不把微信规则复制给支付宝

财付通2026-01-15原始通知明确：微信国际卡单笔不超过人民币200元（含200元）免国际卡手续费；超过200元，按整笔金额的3%计；支付页明示费用与减免；退款按比例退相关手续费。

例：201元的基础手续费是6.03元，不是0.03元。200元不是消费额度上限。优惠、场景适用性和实际收款仍以支付页为准。这是微信规则，不是支付宝规则。

原始通知：https://posts.tenpay.com/posts/9e70c66564910e6002958e997eabb18b.html

支付宝官方开发者介绍可证明支持境外访客关联信用卡，但本轮没有找到可独立核对的当前运营商收费条款页面。旧政府／大学手册和社交帖子不能替代现行合同。因此界面明确显示支付宝收费待核实，并让旅客查看支付宝付款页。没有为了给出完整答案而编造“已核实”。

## 5. 官方网站、照片和社会经验怎么分工

官方访问是白名单内受控抓取：robots检查、同主机重定向、超时、体积限制、缓存标记和失败回退。失败、站点拦截或关键字段变化会记录下来，不伪装访问成功。每次检索不是无限制全网搜索。抓取HTML不等于通过事实语义评审。

浦东官方资料区分入境检查前信息点、行李提取区的SIM/Wi-Fi/换汇区和公共到达区服务中心。没有自行发明“57号登机口”；图片来自官方原页外链、用户点击才加载，不能声称是实时照片、室内导航或自动识图。

社会经验另列为线索：两条公开Reddit讨论、一条社区入口、Duke托管的历史学生手册、X官方账号入口。只有前两条是具体讨论线索；其他不能算抓取了完整帖子库。没有取得小红书或X的批量公开内容，也没有绕过登录、验证码和反爬限制。

社会经验的用途：提出值得验证的任务——扫码方式混淆、外卡和乘车码区别、预注册失败、站内位置不明。政府／服务商的来源负责回答规则。下一步需要授权平台接口或用户有权提供的导出，再做去标识化、去重、人工审核和撤回机制。

## 7. 运营指标与迭代

本版后台展示本机真实交互事件和供应商回执计数，不混入合成游客数量。

- 确认转化：产生需求草稿的会话中，完成需求确认的比例。要按会话与版本去重。
- 需求覆盖：经独立人工标注的需求中，被确认节点覆盖的比例；当前没有独立标签，不展示虚构分数。
- 引用有效：引用ID属于本轮给模型的证据，仅是格式／身份检查。
- 内容支持：节点事实是否真的得到引用支持；需要单独人工或独立评审，不能由ID检查替代。
- 时效与适用：日期、机场、航站楼、公共／受限区域是否匹配。
- 任务结果：用户确认完成、仍卡住、未反馈分别保留；聊天结束不能自动算解决。
- 成本与延迟：实际请求次数、Token回执、超时、回退；不是账号余额和利润。

已实现来源停用、检索日志、请求回退和结果反馈。完整“候选—盲测—灰度—回滚”的策略发布平台尚未在V4重建；此前V3包保留旧模拟流程。后续应把独立失败样本、审核者和成本约束接入，而不是宣传本版已经自动自我优化。

## 8. 已实现与未实现的边界

已实现：普通源码、需求确认、受控官网访问、真实DeepSeek请求代码、输出校验、来源详情、官方图片入口、资料搜索、服务端管理员、使用量回执和测试。

未验证：真实付费DeepSeek响应质量、真实麦克风、所有图片可达性、1,114条内容逐条政策有效性、真实旅客效果、OTA订单／实时柜机库存、支付、人工客服、持续服务SLA。

V4是聚焦“对话+证据+真实接口”的独立入口，不是V3所有模拟功能的无损升级。V3的充电租借订单、邮件EML和旧回放界面仍在原下载包，本轮没有声称全部迁移。
