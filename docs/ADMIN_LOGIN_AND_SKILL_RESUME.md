# Skill改进、运营流程与本地管理员登录

## 为什么Skill应当单独写

本项目的Skill不是泛指一段Prompt，而是运营可改的受限配置：检索数量、分块、覆盖阈值、扩展词和表达要求。手动参数、目标预设和反馈/Loop候选进入自动验收，再由人工看回放与版本后发布，参数进入后续执行；失败可回滚。不能据此宣称模型权重自训练或所有指标已经在线提升。

公开项目简历可分别使用：

- **Skill配置与优化：** 将检索数量、扩展词和表达要求封装为受限Skill，支持手动调参、目标预设与反馈生成候选；经自动验收、回放及人工发布改变后续执行，保留版本核对与回滚。
- **流程运营与指标：** 针对重复追问、遗漏需求与无关推荐，关联反馈及Trace提出流程策略候选，经回归和独立审核发布；结合解决率、反馈覆盖、意图标注及服务外跳定位问题与护栏。

Skill候选与行为流程策略是不同对象：前者在有界字段内由管理员发布；后者保留五个不同审核账号的版本确认。账号规则不意味着已有五位真实运营员工。变更提问顺序、表达长度、延伸建议只能在已有配置范围内，不能任意改工具权限、事实或收费政策。复杂流程仍可能需要工程修改。

## 登录问题与修复范围

旧本机入口读取ADMIN_PASSWORD，而新版Operations读取OPS_USERS_JSON和OPS_SESSION_SECRET。只有旧密码时，新入口可能没有可验证的账号；placeholder也不是真正的输入值。

现在仅在非生产、非Vercel、非SSO、无云存储、仅绑定回环地址且没有已有Operations配置的本机服务，生成与本机ADMIN_PASSWORD一致的加盐账号和进程内签名密钥。默认密码时，服务端确认请求来自实际回环客户端后才允许前端把默认演示值填入输入框；不自动提交，不保存密码到浏览器存储。

已有自定义/部分配置绝不覆盖。自定义密码不返回给浏览器；公网、代理、非回环和生产配置不会获得默认密码。可用LOCAL_DEMO_ADMIN=0关闭这项本地便捷功能。真实线上账号请手动输入或使用原有的私人账号文件导入，不能用DeepSeek Key替代。

当前默认本机演示值为用户名admin、密码demo2026，仅用于没有真实数据的本机演示。输入框增加显示密码选项。线上公开默认管理员会危及私有资料与模型额度，因此没有这样做。

## 本地更新

先停止旧进程，保护.env、运行数据和未提交修改；然后git pull --ff-only origin main、npm ci、npm run build、npm start。若pull有冲突，不使用reset --hard。更新代码后必须重启旧进程，再刷新页面。只打开HTML不具备真实登录后端。

进程内新建签名密钥重启后改变，因此需要重新登录；它不重置资料、反馈、技能或已有私有账号配置。管理员登录、模型已配置、真实模型回答成功仍是三项不同状态。

## 验证边界

新增Node测试检查默认/自定义/生产配置、Host与Origin防伪、实际Operations/SQLite登录与权限；完整服务器测试同时检查旧新两个登录入口。浏览器测试验证输入框value、显示密码、错误密码拒绝、默认及自定义登录、Skill与流程面板可达。最终成绩以对应CI工件为准；不代表用户电脑或生产部署已更新，也不代表模型质量、语音或商业收益验收。

本轮不改变任何原始模型Prompt、检索策略、模型预算、语音逻辑或五账号审核规则；原保留检查与旧回归继续运行。私人简历、实习资料和真实凭据不放在本仓库。
